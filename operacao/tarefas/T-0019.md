# T-0019 - Analise de ameacas do container do ambiente e das opcoes de Docker dos projetos

<!-- Worktree: criado ao aceitar a tarefa (ferramentas/tarefa.sh aceitar T-0019), branch T-0019-descricao-curta -->

## Objetivo

Fazer a analise de ameacas do desenho da T-0018 (container do ambiente 01_IA) antes do Dev, com foco nas 4 opcoes de Docker dos projetos, no login do Claude Code em volume e no que o container enxerga do host, para o humano escolher a opcao de Docker (Q3) e aceitar ou ajustar o ADR-0001.

## Contexto

- Proposto pelo Engenheiro na T-0018 (item 2 do [[COORD-0032]]); depende da T-0018 aprovada (merge dos `docs/`).
- Documentos (projeto `ambiente`): `docs/requisitos/requisitos.md` (RF-01 a RF-25, RNF-01 a RNF-10, Q1 a Q8), `docs/adr/ADR-0001 Arquitetura do container do ambiente.md` (proposta), `docs/modelos/contexto-e-implantacao.md` (diagrama "Docker dos projetos" por opcao), `docs/modelos/caminhos-e-volumes.md`, `docs/avaliacoes/docker-dos-projetos.md` (matriz sem escolha, com 3 perguntas para a Seguranca).
- Notas: [[Docker dentro de container - socket do host equivale a root no host, DinD exige privileged, rootless tem limites]], [[Claude Code em container usa a Dev Container Feature, volume em CLAUDE_CONFIG_DIR e usuario nao root]], [[CWE-250 container como root se evita com USER sem privilegio e cuidado com a posse de volumes]], [[USER sem privilegio nao basta - no-new-privileges e cap_drop ALL fecham a escalada por setuid]].
- Pesquisa pendente: `SEARCH-0010` (managed settings x `CLAUDE_CONFIG_DIR`, Podman aninhado, proxy de socket).

## Criterios de aceite

- [ ] `docs/seguranca/T-0019-ameacas.md` no projeto `ambiente` com fronteiras de confianca (Mermaid), ameacas (STRIDE ou equivalente) com CWE quando houver, risco e mitigacao.
- [ ] Cobre no minimo: (a) cada opcao de Docker (A socket do host, B DinD, C1 socket rootless do host, C2 Podman aninhado) e a variante de A com proxy de socket, respondendo as 3 perguntas da `docs/avaliacoes/docker-dos-projetos.md`; (b) credenciais do Claude Code na pasta montada (`$IA_CLAUDE_DIR`) e o aviso da Anthropic sobre exfiltracao; (c) o que o container enxerga do host (V1, V2, V3; o que fica de fora em RF-08); (d) escrita nas areas N4 e a proposta de montagem somente leitura (RF-25, Q8); (e) rede de saida e firewall (Q4); (f) identidade do git sem credencial de push (RF-12); (g) RNF-02/RNF-03 (`cap_drop`, `no-new-privileges`) e se algum requisito do desenho os contraria; (h) **confinamento do agente ao projeto** (decisao do humano, RF-26 a RF-30): o sandbox do Claude Code dentro de um container sem privilegio (`enableWeakerNestedSandbox`, namespaces de usuario sob o perfil padrao do Docker), o que ele nao cobre (ferramentas de arquivo, MCP, hooks) e se o plano B (um container por tarefa) e necessario; (i) rede e leitura por papel ja decididas pelo humano (Q4: so o Pesquisador na internet, demais so git e `localhost`, pelo sandbox; Q10: papel de worktree le so a propria tarefa e o BRAIN; RF-31 a RF-34): o que o sandbox nao cobre (trafego do proprio Claude Code, `WebFetch`, daemon do Docker) e se o firewall completo ainda e necessario.
- [ ] **Q3 foi delegada ao Engenheiro** (2026-10-05), que recomenda **C1 + filtro no socket** (Docker rootless no host + intermediario que so aceita montagens dentro do worktree da tarefa e recusa container privilegiado). Confirmar ou refutar essa recomendacao, com o filtro concreto (existe projeto mantido? que garantias declara? `SEARCH-0010` item 5) e o que acontece se o filtro for contornado.
- [ ] Recomendacao de seguranca sobre a opcao de Docker (a escolha continua do humano), com o que cada opcao exige como mitigacao minima e **se ela consegue cumprir RF-30** (eliminatorio).
