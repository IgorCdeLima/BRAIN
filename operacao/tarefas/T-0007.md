# T-0007 - Cabecalhos de seguranca HTTP em todas as respostas (SEC-0005)

## Objetivo

Corrigir o SEC-0005: a pagina e as demais respostas passam a enviar cabecalhos contra clickjacking, sniffing de tipo e carga de recurso de outra origem (RNF-08, proposto na T-0006).

## Contexto

- Origem: T-0006 (Engenheiro). Requisito: RNF-08 em `docs/requisitos/requisitos.md`, secao "Proposto pela T-0006".
- Registro: `qualidade/seguranca/SEC-0005.md` (baixa).
- Nota do Brain (rascunho, testar e informar o resultado ao Bibliotecario): [[CWE-1021 clickjacking se evita com CSP frame-ancestors e X-Frame-Options em middleware do Starlette]]. Ela traz o middleware ASGI puro; o `add_middleware` do FastAPI nao foi conferido em fonte.
- **Armadilha:** o CSS da pagina esta num `<style>` dentro de `app/templates/index.html`. `default-src 'self'` sem `style-src 'unsafe-inline'` bloqueia esse estilo (MDN, `style-src`). A premissa da T-0006, **aceita pelo humano em 2026-09-30**, e permitir `'unsafe-inline'` so em `style-src` ate o CSS ir para arquivo.
- **Armadilha:** o middleware `limitar_requisicao` responde 411/413 antes do handler. O middleware de cabecalhos tem de ficar **por fora** dele para cobrir essas respostas tambem.
- `interface: nao`: nada muda na tela; o criterio 3 confere que o estilo continua aplicado.
- `seguranca: sim` (controle de seguranca). Sugestao para a triagem: dispensar a analise de ameacas previa, porque a solucao ja esta definida aqui; manter a revisao da Seguranca.

## Criterios de aceite

- [ ] Toda resposta da aplicacao envia exatamente:
  - `Content-Security-Policy: default-src 'self'; img-src 'self'; style-src 'self' 'unsafe-inline'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'; object-src 'none'`
  - `X-Frame-Options: DENY`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
- [ ] Testes automaticos conferem os 4 cabecalhos em: `GET /` (200), `POST /produtos` invalido (422), `POST /produtos` valido (303), `POST` sem `Content-Length` (411), `POST` acima de 10 MB (413), `GET /uploads/<nome gerado>` (200), `GET /uploads/x.svg` (404) e `GET /health`.
- [ ] Pagina no navegador (porta da tarefa): estilo aplicado como antes, cadastro com imagem funciona, imagem aparece na listagem, **nenhuma** violacao de CSP no console. Se o navegador nao estiver disponivel, registrar como NAO verificado.
- [ ] `/uploads/<nome>` continua com um unico `X-Content-Type-Options` (nao duplicado).
- [ ] `docker compose run --build --rm test` e `docker compose run --build --rm lint` passam.
- [ ] SEC-0005 fica pronto para a Seguranca verificar (o Dev nao altera `qualidade/`; registrar `commit_correcao` na Entrega).

## Restricoes / o que NAO fazer

- Nao mover o CSS para arquivo nem mudar o visual (seria tarefa com `interface: sim`).
- Nao usar `<meta http-equiv>` para a CSP: `frame-ancestors` so vale como cabecalho.
- Nao mexer nos limites de upload.
