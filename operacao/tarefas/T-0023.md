# T-0023 - Codex CLI no container do ambiente, com credencial propria e confinamento equivalente

## Objetivo

Instalar o Codex CLI na imagem do ambiente, com a credencial (assinatura do humano) numa pasta do host so dele, para o humano validar o login e usar o Codex dentro do container. Nenhum papel do 01_IA passa a usar o Codex nesta tarefa: isso e da fase 4 (T-0022).

## Contexto

- Decisao do humano (Q9 da T-0018, 2026-10-05): "a ideia e ja ir implementando, se precisar eu tenho um login do codex para validar e adicionar". O Engenheiro propos um cartao proprio logo depois da T-0020, para nao atrasar a imagem base.
- Pre-requisitos: T-0020 concluida; analise da Seguranca da T-0019 (ou um complemento dela) cobrindo o Codex; `SEARCH-0010` item 7 respondido (como o Codex CLI se instala, onde guarda a credencial e que confinamento oferece).
- Requisitos do projeto `ambiente`: premissa P8 (uma pasta de credencial por ferramenta), RF-08 (nada alem do documentado e montado), RF-26 a RF-29 (confinamento ao projeto), RNF-11 (nada pessoal versionado). As protecoes do 01_IA (hooks, perfis, `restringir_escrita.py`) sao do Claude Code e **nao** valem para o Codex.

## Criterios de aceite

- [ ] Codex CLI instalado pela forma oficial (fonte e data no roteiro); versao registrada; atualizacao seguindo a decisao Q5 (atualizar sempre que possivel), se o Codex permitir.
- [ ] Credencial do Codex numa pasta do host so dele (`IA_CODEX_DIR` ou nome equivalente, com as mesmas regras de validacao de `IA_CLAUDE_DIR`), montada no local que o Codex usa; sobrevive a `down`/`up`; nada no repositorio nem na imagem (RNF-01, RNF-11).
- [ ] O humano faz o login do Codex dentro do container e roda um comando simples num worktree de teste.
- [ ] Confinamento: os comandos que o Codex executa nao escrevem fora do worktree em que foi aberto (mesmo teste de RF-27). Se o Codex nao oferecer isso dentro do container, registrar e **nao** liberar o Codex para trabalho real ate a Seguranca e o humano decidirem.
