# T-0009 - Dependencias travadas com hash (SEC-0003) e comandos com --build (O1)

## Objetivo

1. Corrigir o SEC-0003: toda dependencia Python, direta e indireta, instalada com versao exata e hash (RNF-06), conforme o ADR-0003 (pip-tools).
2. Confirmar a observacao O1 (VER-0009/VER-0010) e documentar `run --build` para `test`, `lint` e `audit` (RNF-10).

## Criterios de aceite

**Parte 1 - confirmar a O1 (antes de mudar qualquer arquivo de dependencias)**

- [ ] Numa copia descartavel do commit atual (ex.: `git archive HEAD | tar -x -C <scratchpad>/o1`), com projeto Compose proprio `-p t0009-o1`:
  1. `docker compose -p t0009-o1 --profile test build audit test` e `docker compose -p t0009-o1 run --rm --no-deps audit` -> registrar a saida (esperado: "No known vulnerabilities found").
  2. Acrescentar `urllib3==1.26.0` ao `requirements-dev.txt` **da copia**. Rodar `run --rm --no-deps audit` **sem** `--build` -> registrar (esperado: continua limpo, resultado desatualizado).
  3. Rodar `run --build --rm --no-deps audit` -> registrar (esperado: urllib3 acusado, codigo de saida 1).
  4. Na copia, trocar uma mensagem em `app/imagens.py` para quebrar um teste existente. `run --rm test` sem `--build` -> registrar (esperado: passa, codigo velho); com `--build` -> registrar (esperado: falha).
  5. Limpar: `docker compose -p t0009-o1 down` e apagar a copia. Os volumes `t0009-o1_*` vao para "Pedidos ao Coordenador".
- [ ] Resultado da Parte 1 na Entrega, confirmando ou nao a O1 para `audit` e para `test`.

**Parte 2 - travamento (ADR-0003)**

- [ ] `requirements.in` (diretas da runtime) e `requirements-dev.in` (`-c requirements.txt` + diretas de dev) versionados; versoes das diretas mantidas as atuais, salvo se o `pip-audit` pedir outra.
- [ ] `requirements.txt` e `requirements-dev.txt` gerados por `pip-compile --generate-hashes`, com cabecalho dizendo o comando que os gera; toda linha com `==` e ao menos um `--hash=sha256:`.
- [ ] Servico do Compose so para gerar os travados (ex.: `lock`, profile proprio), sobre a mesma imagem Python do `Dockerfile`, com pip e pip-tools em versao fixa; `docker compose run --rm lock` regenera os dois arquivos. A imagem `runtime` e a `dev` nao tem `pip-tools` (`pip show pip-tools` -> nao encontrado).
- [ ] `Dockerfile` instala com `pip install --no-cache-dir --require-hashes -r ...` nos estagios `base` e `dev`.
- [ ] Teste negativo registrado: remover um hash (ou trocar `==` por `>=`) numa copia -> o build falha.
- [ ] `audit` audita os arquivos travados (`pip-audit --require-hashes -r requirements.txt -r requirements-dev.txt` ou equivalente documentado) -> "No known vulnerabilities found"; e o teste negativo com uma versao vulneravel da codigo de saida 1.
- [ ] A contagem do SEC-0003 fecha: `pip freeze` da imagem dev e da runtime so tem pacotes presentes no arquivo travado correspondente (registrar as duas contagens).

**Parte 3 - documentacao (RNF-10)**

- [ ] README: comandos `docker compose run --build --rm test`, `... lint`, `... audit` e `docker compose run --rm lock`, com uma frase sobre por que o `--build` (O1) e como atualizar uma dependencia (editar o `.in`, rodar `lock`, commitar os dois arquivos).
- [ ] Linhas equivalentes para o `CLAUDE.md` do projeto (area N4) em "Pedidos ao Coordenador", com o texto exato.
- [ ] `docker compose run --build --rm test`, `lint` e `audit` passam; `GET /health` 200.
