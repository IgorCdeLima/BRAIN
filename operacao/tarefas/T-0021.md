# T-0021 - Docker dos projetos a partir do container do ambiente (opcao escolhida pelo humano)

<!-- Worktree: criado ao aceitar a tarefa (ferramentas/tarefa.sh aceitar T-0021), branch T-0021-descricao-curta -->

## Objetivo

Permitir que os papeis rodem o Docker Compose do lab a partir do worktree no container (RF-22), com a opcao que o humano escolher depois da analise da Seguranca (Q3), registrada num ADR do projeto `aceito` (RF-23).

## Contexto

- Proposto pelo Engenheiro na T-0018. Pre-requisitos: T-0020 concluida; T-0019 concluida; **ADR do projeto com a opcao escolhida em `aceita`** (o Engenheiro ou o Coordenador redige a partir de `docs/avaliacoes/docker-dos-projetos.md`; o humano aceita).
- Documentos: `docs/requisitos/requisitos.md` (RF-22, RF-23, RNF-02, RNF-05), `docs/avaliacoes/docker-dos-projetos.md`, `docs/modelos/contexto-e-implantacao.md`, `docs/seguranca/T-0019-ameacas.md`.
- Uso real do lab: `projetos/lab/CLAUDE.md` (portas 8000-8399 por papel e tarefa, `docker compose run --build --rm test`, nunca `down -v`).

## Criterios de aceite

- [ ] Do worktree de uma tarefa do lab no container: `docker compose run --build --rm test` passa; `APP_PORT=800N docker compose up -d --build` sobe e o humano abre `http://localhost:800N` no navegador do host; `docker compose down` para (RF-22).
- [ ] Bind mounts relativos do lab (`./app`, `./tests`) mostram os arquivos do worktree (conferido com uma mudanca de teste).
- [ ] **RF-30 (eliminatorio):** a partir de uma sessao de papel, subir um container que monte pasta fora do worktree da tarefa (ex.: `docker run -v "$IA_RAIZ":/x ...`) ou um container privilegiado e recusado. Os dois casos no roteiro. O sandbox (RF-26/RF-27) continua ativo; se a opcao exigir `excludedCommands`, isso esta no ADR da opcao com a analise da Seguranca.
- [ ] Arquivos gerados pelo servico `lock` (`user: 1000:1000`) ficam com o dono do humano no host.
- [ ] Mitigacoes minimas da opcao, vindas da T-0019, implementadas e verificadas uma a uma.
- [ ] O que a opcao muda no host (se mudar) descrito no README com o comando exato, e executado pelo humano.
- [ ] RNF-02/RNF-05 atualizados no `docs/requisitos/requisitos.md` para a excecao aprovada no ADR, no mesmo commit.

## Restricoes / o que NAO fazer

- Nao comecar sem o ADR da opcao `aceita`.
- Nao mudar o Docker do host (instalar rootless, permitir privileged) sem o comando ir ao humano via `COORD-####`.
- Nunca `docker compose down -v` no lab.
