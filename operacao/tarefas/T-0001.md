# T-0001 — Esqueleto da aplicação com FastAPI e PostgreSQL no Docker

## Objetivo

Ter a aplicação mínima rodando no Docker Compose, conectada ao PostgreSQL, com verificação de saúde e testes automatizados — a base para as próximas tarefas.

## Contexto

- Projeto: `D:\01_IA\projetos\lab` (ler `CLAUDE.md`).
- Stack: `docs/adr/ADR-0001 Stack do projeto.md`.
- Requisito: RF-01 e RNF-01 a RNF-03 em `docs/requisitos/requisitos.md`.
- Modelos: `docs/modelos/modelos.md` (containers).

## Critérios de aceite

- [ ] `docker compose up -d --build` sobe os serviços `app` e `db`; a aplicação responde em `http://localhost:8000`.
- [ ] O serviço `db` tem healthcheck e o `app` só inicia depois que o banco está saudável.
- [ ] `GET /health` retorna `200` com `{"status": "ok", "banco": "ok"}` quando o banco responde, e `503` quando não responde.
- [ ] `GET /` retorna uma página HTML (Jinja2) com o título "Cadastro de produtos" (conteúdo provisório).
- [ ] `docker compose run --rm app pytest` passa, com pelo menos: saúde OK, saúde com banco indisponível, página inicial.
- [ ] Configuração por variáveis de ambiente; `.env.example` lista todas. O Compose funciona **sem** `.env`, usando valores padrão **apenas para desenvolvimento local**, marcados como tal.
- [ ] Versões fixadas em `requirements.txt` e nas imagens Docker, escolhidas após consultar a documentação oficial (registrar na Entrega quais versões e onde verificou).
- [ ] `README.md` do projeto atualizado com como subir e testar.

## Restrições / o que NÃO fazer

- Não implementar cadastro de produtos (é a T-0002).
- Não criar nem ler `.env` (bloqueado por permissão); usar `.env.example` e valores padrão de desenvolvimento.
- Não usar `docker compose down -v`.
- Não alterar `CLAUDE.md`, `.claude/`, `.githooks/` nem `qualidade/`. Se algo neles estiver errado, anotar em "Dúvidas em aberto".
